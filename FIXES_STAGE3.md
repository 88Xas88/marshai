## ПРАВКА 1 — Датапикер на главной странице

**Файл:** `components/search/SearchForm.tsx`

**Проблема:** поле "Когда · Дней" — ручной ввод текста. Неудобно.

**Что сделать:**

Заменить текстовое поле дат на два поля:
- **Туда** — `<input type="date">` с иконкой календаря
- **Обратно** — `<input type="date">` с иконкой календаря
- **Дней** — оставить как есть (ручной ввод числа ИЛИ выпадающий список 1–14)

На десктопе три поля в одну строку: `[Туда: дата] [Обратно: дата] [Дней: число]`

На мобайле стековать вертикально.

**Логика:**
- При выборе дат — автоматически считать кол-во дней и подставлять в поле "Дней"
- При ручном вводе "Дней" — не менять даты
- Минимальная дата — сегодня (нельзя выбрать прошлое)
- Дата "Обратно" не может быть раньше "Туда"

**Параметры в URL остаются теми же:**
`/generating?from=...&to=...&dates=10-15.05&days=5`

## ПРАВКА 2 — Защита страницы /account

**Файл:** `app/account/page.tsx`

**Проблема:** `/account` открывается без авторизации и показывает mock-данные любому пользователю. Это выглядит непрофессионально.

**Что сделать:**

Добавить простую проверку авторизации на странице `/account`.

**Вариант А (минимальный, без OAuth — рекомендую на старте):**

Если пользователь не авторизован — показывать экран входа прямо на `/account`:

```
┌─────────────────────────────────┐
│         M  Marshai              │
│                                 │
│   [иконка пользователя 48px]    │
│                                 │
│   Мои поездки                   │
│   Сохраняй планы и следи        │
│   за изменением цен             │
│                                 │
│   [email поле]                  │
│   [Войти / Зарегистрироваться]  │
│                                 │
│   или                           │
│                                 │
│   [G  Войти через Google]       │
│                                 │
│   Нажимая "Войти", вы           │
│   соглашаетесь с условиями      │
└─────────────────────────────────┘
```

**Реализация:**
- Использовать `localStorage` для хранения email после входа (простая имитация сессии)
- При вводе email + нажатии кнопки — сохранить в `localStorage` и показать страницу с поездками
- При обновлении страницы — проверять `localStorage`, если email есть — показывать аккаунт
- Кнопка "Выйти" в настройках — очищать `localStorage` и возвращать на экран входа
- Кнопка Google — пока UI-заглушка (реальный OAuth через NextAuth подключим позже)

**Технически:**
```typescript
// В app/account/page.tsx
const [userEmail, setUserEmail] = useState<string | null>(null)

useEffect(() => {
  const email = localStorage.getItem('marshai_user_email')
  setUserEmail(email)
}, [])

if (!userEmail) {
  return <LoginScreen onLogin={(email) => {
    localStorage.setItem('marshai_user_email', email)
    setUserEmail(email)
  }} />
}

return <AccountPage email={userEmail} />
```

**Дизайн экрана входа:**
- Фон: `var(--color-background-tertiary)`
- Карточка по центру, max-width 400px, border-radius 12px
- Логотип Marshai вверху
- Поле email: стандартный инпут
- Кнопка "Продолжить": background #2C2C2A, полная ширина
- Кнопка Google: белая с бордером, иконка G слева
- font-weight 400/500, никаких теней и градиентов
